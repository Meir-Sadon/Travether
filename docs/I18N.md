# Translations and right-to-left

The UI ships in English; Hebrew (right-to-left) is planned for Phase 2 (PLAN.md §7). Everything needed for it is in place now so adding a language is mostly translation work.

## How strings work

- [i18next](https://www.i18next.com/) + `react-i18next`, set up in [`frontend/src/i18n/index.ts`](../frontend/src/i18n/index.ts).
- Strings live in [`frontend/src/i18n/locales/en.json`](../frontend/src/i18n/locales/en.json), grouped by screen. Components call `const { t } = useTranslation()` and `t('status.api', { state })`. Keys are type-checked: a typo fails `npm run typecheck`.
- The language is picked from a saved choice (`localStorage['travether.lang']`), then the browser language, then English.
- `<html lang dir>` follows the language automatically (`dir="rtl"` for Hebrew/Arabic), so the browser, screen readers and CSS all switch together.

## Adding a language

1. Copy `locales/en.json` to `locales/<code>.json` and translate it.
2. Import it in `i18n/index.ts` and add the code to `supportedLanguages` and `resources`.
3. Check the screens with that language selected; for RTL, look for icons or images that should mirror.

## Logical CSS (RTL-ready layouts)

Styles use logical properties, so the same CSS lays out correctly in both directions:

| Instead of | Use |
|------------|-----|
| `margin-left`, `padding-right` | `margin-inline-start`, `padding-inline-end` |
| `left: 0`, `right: 0` | `inset-inline-start: 0`, `inset-inline-end: 0` |
| `text-align: left` | `text-align: start` |
| `border-top-left-radius` | `border-start-start-radius` |
| `width`, `height` (optional) | `inline-size`, `block-size` |

The test [`logical-css.test.ts`](../frontend/src/i18n/logical-css.test.ts) fails on physical left/right properties in any stylesheet or inline style. If one is genuinely needed, add a `physical-ok` comment on that line. Directional icons (back, forward, send) mirror automatically in RTL through the `Icon` component.
