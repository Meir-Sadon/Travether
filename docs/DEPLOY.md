# Deploying Travether

Production runs as **one Docker web service on Render** (the API serves the built frontend) plus a **Neon PostgreSQL** database in the EU. The Blueprint is [`render.yaml`](../render.yaml) and the image is the root [`Dockerfile`](../Dockerfile).

## 1. Database (Neon)

1. Create a Neon project in an EU region (Frankfurt matches the Render region).
2. Enable PostGIS on the database: open the SQL editor and run `CREATE EXTENSION IF NOT EXISTS postgis;` (the first migration also does this, but Neon may require the owner role to create extensions).
3. Copy the connection details and build an Npgsql connection string:

   ```
   Host=<host>;Database=<db>;Username=<user>;Password=<password>;SSL Mode=Require
   ```

## 2. Render

1. In Render, choose **New → Blueprint** and pick this repository. Render reads `render.yaml`.
2. Fill in the variables marked `sync: false`:

   | Variable | Value |
   |----------|-------|
   | `ConnectionStrings__Default` | The Npgsql string from step 1 |
   | `Cloudinary__Url` | `cloudinary://<api_key>:<api_secret>@<cloud_name>`. **Needed for profile photos and covers in production**: without it, uploads go to the container's disk, which Render wipes on every deploy. |
   | `Places__PhotonUrl` | Optional. Meeting-point search uses the public [Photon](https://photon.komoot.io) geocoder (OpenStreetMap, no key) until a map provider is chosen; set this to point at another Photon instance. |
   | `Email__ResendApiKey`, `Email__From` | Resend API key and a sender on a verified domain, e.g. `Travether <hello@travether.app>`. **Needed for sign-in codes**; while empty, emails are only written to the log. |
   | `Push__VapidPublicKey`, `Push__VapidPrivateKey`, `Push__Subject` | Web Push keys (generate once with `npx web-push generate-vapid-keys`; the private key is a secret) and a contact such as `mailto:hello@travether.app`. Without keys push is off in production; changing keys makes every device subscribe again. |
   | `Notifications__PublicUrl` | The app's public address, e.g. `https://travether.onrender.com`, for links in notification emails. |
   | `Auth__GoogleClientId` | OAuth 2.0 *Web* client id from Google Cloud Console (authorized JavaScript origin: the site URL). Empty hides the Google button. |
   | `Auth__AppleClientId`, `Auth__AppleRedirectUri` | Sign in with Apple *Services ID* and the return URL registered for it (the site URL works). Empty hides the Apple button. |

   `Jwt__Secret` is generated by Render. `Database__MigrateOnStartup=true` applies EF Core migrations when the service starts.
3. Deploy. Render builds the Dockerfile and checks `GET /api/health`.

## 3. Moderators

There is no sign-up for moderators. Make an existing account one in the database (Neon SQL editor):

```sql
UPDATE users SET role = 'moderator' WHERE email = 'you@example.com';
```

They then see **Settings → Moderation** (`/admin`). Rate limits can be tuned with `RateLimits__JoinRequestsPerHour` (20), `RateLimits__MessagesPerMinute` (30), `RateLimits__ReportsPerDay` (20) and `RateLimits__SignupsPerIpPerDay` (20).

## 4. Checking a deploy

- `https://<service>.onrender.com/api/health` returns `{"status":"ok",...}`.
- Any other path serves the React app.

The free Render plan sleeps after inactivity; the first request after a sleep takes a few seconds.
