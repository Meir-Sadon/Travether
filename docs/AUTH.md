# Authentication (step 1.1)

Who you are is decided here; what you may see is decided by [AUTHORIZATION.md](AUTHORIZATION.md).

## Sign-in methods (PLAN.md decision 2)

| Method | Flow | Email verified? |
|--------|------|-----------------|
| Email code | `POST /api/auth/email/start` → 6-digit code by email → `POST /api/auth/email/verify` | Yes |
| Google | Google Identity Services button → ID token → `POST /api/auth/external` | Yes (Google's `email_verified`) |
| Apple | Sign in with Apple JS popup → ID token → `POST /api/auth/external` | Yes |
| Password | `POST /api/auth/register` with email + password; later `POST /api/auth/login` | After `POST /api/auth/email/confirm` with the emailed code |

No national ID, ever. SMS codes are not in the MVP (they need a paid SMS vendor); the phone field stays optional.

**Verify first, create later.** A code, Google or Apple sign-in for an unknown email returns `needsProfile` with a 30-minute signed **sign-up token**. The onboarding wizard's "About you" step sends it to `POST /api/auth/register` with first name, last name, date of birth and country. The API refuses anyone under 18 (`Underage`) and anyone who hasn't accepted the terms (`TermsRequired`), and records `terms`, `privacy_policy` and `community_guidelines` consents with the current legal version (`Auth:LegalVersion`).

Google or Apple sign-in with a verified email that already has an account links the provider to that account. Proving control of the email earns the ✉️ contact-verified badge.

## Sessions

- A JWT (HMAC-SHA256, key `Jwt:Secret`) in the **httpOnly, SameSite=Lax** cookie `tv_session`, `Secure` over HTTPS, valid 30 days. JavaScript never reads it; the app asks `GET /api/auth/me`.
- The token carries the user's `session_version`. Every request re-checks the user: a ban, deletion, "log out everywhere" (`POST /api/auth/logout-all`) or a password reset bumps or invalidates it, and old cookies stop working at once.
- **CSRF:** every non-GET `/api` request must send `X-Travether-Csrf: 1` (the frontend's `api` helper does). Browsers can't add custom headers to cross-site forms, and cross-origin fetches with one need a CORS preflight this API never allows.

## One-time codes

Six digits from a CSPRNG, stored as an HMAC (never in clear), valid 10 minutes, single use, dead after 5 wrong guesses. Only the newest code per address and purpose works, and an address gets at most 5 codes per hour (`TooManyCodes`). `email/start` and `password/forgot` always answer 202, so they don't reveal whether an account exists; wrong email and wrong password give the same `InvalidCredentials`.

Auth endpoints are also rate-limited per IP (`RateLimits:AuthPerMinute`, default 20).

## Configuration

| Setting | Purpose |
|---------|---------|
| `Jwt__Secret` | Signing key (≥ 32 chars). Generated by Render. Development and tests use a fixed non-secret key. |
| `Auth__GoogleClientId` | Google OAuth web client id. Empty hides the button. |
| `Auth__AppleClientId`, `Auth__AppleRedirectUri` | Apple Services ID and its registered return URL. Empty hides the button. |
| `Email__ResendApiKey`, `Email__From` | Sends codes through Resend. Empty: emails are written to the API log (local development). |

Passwords are hashed with ASP.NET Core Identity's `PasswordHasher` (PBKDF2), 8–128 characters.
